# CasinoCraft 26.3 – Slots GUI + Shared Roulette (source preview)

This update is based on the previous `CasinoCraft-26.3-compile-fix.zip` source, retaining horse racing, blackjack and higher/lower.

## Install / build

Upload the **contents** of this project to your GitHub repository, including `.github/workflows/build.yml`. Run the GitHub Actions Gradle build with Java 25 and Gradle 9.8.0. Download the JAR artifact **only after** the build succeeds, and first test on a copied world. This source has NOT been successfully compiled or tested against Fabric 26.3 in this environment.

## How to place the games

As OP, stand next to a placed block (player heads, levers, barrels are allowed) and look at it:

- `/casino block set slots`
- `/casino block set roulette`
- `/casino block set blackjack`
- `/casino block set horse`
- `/casino block set higherlower`
- `/casino block remove`

Only the block at that position is registered. Right-clicking an eligible slots or roulette block should open a vanilla 6-row chest screen (without any client mod). The other three games still use the previous clickable-chat UI.

## Slots

- Slots appear as 3 item reels in the chest GUI, animated server-side for ~1.5 seconds.
- Bet size buttons: 1, 5, 10, 32, 64 diamonds; a lever item triggers a spin.
- Symbols: Diamond, Emerald, Gold Ingot, Redstone, Amethyst Shard, Nether Star.
- Triple symbol multipliers (total payout): 12x, 9x, 7x, 5x, 4x, 25x respectively.
- Double symbol multipliers: 3x, 2x, 2x, 1x, 1x, 5x respectively.
- No match: no payout. A bet is deducted immediately; the chosen outcome is server-side.
- Pending spins are saved to the ledger, and refunded on server restart if unresolved.

## Roulette

- **Each registered roulette block is a separate table** with one shared round for everybody using it.
- The first confirmed wager starts a 45-second countdown. More players can join the same round.
- Clicking each wager cell commits that wager immediately and deducts diamonds.
- Multiple bets per player are allowed, up to 64 chips and a total of 256 diamonds per round.
- Numbers 0-36 (pages), red, black, even/odd, low/high, dozens, columns.
- A floating vanilla text-display entity appears above that registered block, showing time left, a rolling number during the last five seconds, and the final result.
- A single winning number (0–36) applies to ALL player bets for this table. Winnings generated by the server and stored as pending credits.
- On restart, any unsettled roulette bets are refunded using the saved ledger.
- Settle records and game state should be stress-tested with disconnects and forced crashes before live use; do not use on the main economy until verified.

## Known constraints

- This is a **source preview**, not a verified build or ready-to-use JAR. The GitHub Actions log will identify any remaining Minecraft 26.3 API compile incompatibilities.
- Vanilla chest GUI only; no custom client graphics/sound.
- Roulette animation uses rapidly changing text above the block in the last five seconds, rather than an actual rotating model.
- Money persistence is a best-effort JSON ledger. There is still a potential crash window between removing a stake and saving the ledger, so test on a copy before allowing real SMP diamond wagers.
- The prior horse system and other game modes remain prototype-quality.


## GUI and roulette wheel expansion (November 2026)
- Roulette number buttons are displayed clockwise in the *actual European single-zero wheel order*: `0, 32, 15, 19, 4, 21, 2, 25, 17, 34, 6, 27, 13, 36, 11, 30, 8, 23, 10, 5, 24, 16, 33, 1, 20, 14, 31, 9, 22, 18, 29, 7, 28, 12, 35, 3, 26`.
- Roulette shared table opens betting for **10 seconds** from the first bet, then resolves one single result for all bettors. Floating TextDisplay shows a cycling wheel-order number during the final five seconds.
- Blackjack and Higher-or-Lower are now controlled through standard 6-row vanilla chest GUIs.
- Horse racing GUI shows five dyed leather horse armor items with horse name, hex color, chance and payout. The GUI uses existing /casino horse color/chance/payout configuration.
- All players still join by right-clicking their registered block (including levers/player heads). No custom client mod is needed.

### Important testing limitation
This source has **not been compiled or runtime-tested** against Minecraft 26.3; use the included GitHub Actions workflow and test with disposable diamonds on a staging server before enabling for players. In particular, verify that all slot clicks are handled safely and that offline payout and crash recovery are correct. The existing blackjack logic is a simplified card game, not a full official blackjack rules engine.
